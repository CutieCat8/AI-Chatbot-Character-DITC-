# ADR: ทดสอบ STT ด้วยเสียงคนจริง — ผลลัพธ์และการตัดสินใจ

- **สถานะ:** ตัดสินใจแล้ว (2026-09-06)
- **บริบท:** ก่อนหน้านี้ทดสอบ voice pipeline ด้วยเสียง TTS สังเคราะห์เท่านั้น (`spike_gemini_live_audio_in.py`)
  ยังไม่เคยพิสูจน์ด้วยเสียงคนจริงเลยสักครั้ง ทั้งที่สภาพหน้าบูธจริงมีเสียงรบกวนและสำเนียงคนจริงต่างจาก TTS
  มาก — จำเป็นต้องรู้ก่อนตัดสินใจว่าจะไล่แก้ STT เพิ่มไหม (เช่นเพิ่ม alias คำที่ฟังผิด)

## ชุดทดสอบ

อัดเสียงจริงจากคนในทีม 2 คน คนละ 5 ประโยค × 2 สภาพ (เงียบ/มีเสียงรบกวน) = 20 ไฟล์ (`.m4a`)
ยืนห่างไมค์ ~1 เมตร (จำลองระยะจริงหน้าตู้)

**เงื่อนไข "มีเสียงรบกวน" (noisy):** เปิดพอดแคสต์ภาษาไทยจากลำโพงห่างผู้พูดประมาณ 2-3 เมตร ระดับเสียง
ปานกลาง อัดตอนกลางคืนในหอพัก (ไม่ใช่เสียงรบกวนแบบสุ่ม — เลือกพอดแคสต์เพราะมีเสียงพูดภาษาไทยปนอยู่
ใกล้เคียงสถานการณ์หน้าบูธที่มีคนคุยกันรอบข้างมากกว่าเสียง white noise)

**5 ประโยคทดสอบ** (มีคำเฉพาะ CAMT, DITC, SE, DII, MMIT):
1. อยากทราบว่าคณะ CAMT มหาวิทยาลัยเชียงใหม่คืออะไร
2. ศูนย์ DITC คืออะไร ทำอะไรบ้าง
3. ค่าเทอมของสาขาวิศวกรรมซอฟต์แวร์ SE เท่าไหร่
4. สาขา DII เรียนเกี่ยวกับอะไร ต่างจาก SE ยังไง
5. อยากสมัครเรียนสาขา MMIT ต้องมีคุณสมบัติอะไรบ้าง

**ทำไมข้อ 5 เปลี่ยนจาก DTM เป็น MMIT:** ชุดคำถามเดิม (ทดสอบด้วย TTS) ใช้ DTM ซึ่งเป็นหลักสูตร
**ปริญญาโท** — แต่ผู้ใช้ส่วนใหญ่ที่จะเดินมาคุยกับหุ่นยนต์หน้าบูธเป็นกลุ่มที่สนใจเข้าเรียนระดับ
**ปริญญาตรี** มากกว่า จึงเปลี่ยนเป็น MMIT (ปริญญาตรี) ให้สะท้อนคำถามจริงหน้างานมากกว่า

## บั๊กที่พบและแก้ในกระบวนการวัดผลเอง (สำคัญ — ต้องรู้ก่อนอ่านตัวเลขข้างล่าง)

รอบแรกวัด "STT ถอดคำตรงตัวอักษร CAMT/DITC/... เจอไหม" แบบ substring match ตรง ๆ ได้ผล
**12/20 = 60%** — แต่วิธีวัดนี้มีบั๊ก: **"CAMT" ที่พูดจริงออกเสียงเป็น "แคมป์" การถอดเป็นอักษรไทยแบบนี้
คือถูกต้อง ไม่ใช่ฟังผิด** (แค่คนละสคริปต์) เกณฑ์เดิมเช็คแค่ตัวอักษรละตินเลยตัดสินผิดทุกครั้ง แก้โดยแยก
"การถอดเสียงข้ามสคริปต์ที่สมเหตุสมผล" ออกจาก "ฟังผิดคำ" ชัดเจน (`ACCEPTED_TRANSLATIONS` ใน
`test_real_voice_stt.py` — ของ DITC ใช้ `_DITC_ALIASES` ตัวเดียวกับ `retrieval.py` เป็น single
source of truth) หลังแก้: **16/20 = 80%**

แยกตามคำ (แก้บั๊กแล้ว): CAMT 4/4, SE 4/4, DII 4/4, MMIT 4/4, **DITC 0/4** — DITC ยังฟังผิดจริง
("Disney", "DC", "Sound Research C") ซึ่งเป็นการฟังผิดคำจริง ไม่ใช่การถอดเสียงข้ามสคริปต์

## ทดลอง 2 ทาง ก่อนพิจารณา alias (แก้ที่ต้นเหตุก่อนไล่ map ปลายเหตุ)

| ทาง | ผล |
|---|---|
| **Vocabulary priming** (`custom_vocabulary=["CAMT","DITC","SE","DII","MMIT"]` ใน `AudioTranscriptionConfig`) | **ไม่ได้ผล** — DITC ยังฟังผิดเป็น Disney/DC เหมือนเดิมทุกไฟล์ recall เท่าเดิม 80% |
| **ล็อกภาษาเป็นไทย** (`language_codes=["th-TH"]` แทน auto-detect) | **ได้ผลจริง** — พบว่า `person2-qstn5-noisy.m4a` (เงียบสนิทเหมือนไฟล์อื่น ไม่มีเหตุผลชัดเจน) ถูก auto-detect เดาเป็น**ภาษาอินโดนีเซียทั้งประโยค** ("Ya, semangat kuliah cabang MMIT, Bu...") พอล็อก th-TH แล้วถอดถูกสมบูรณ์ทันที |

**ตัดสินใจ:** ล็อกภาษาไทยเสมอ (ใส่แล้วใน `voice_pipeline_dev.py`) — ไม่เพิ่ม custom_vocabulary
(ไม่มีหลักฐานว่าช่วยอะไร เพิ่มความซับซ้อนโดยไม่จำเป็น) และ**ไม่เพิ่ม alias คำ CAMT/DITC ใน
`normalize_query()`** ด้วยเหตุผลในหัวข้อถัดไป

## ตัวเลขที่สำคัญจริง: วัด "คำตอบถูก" ผ่าน full pipeline ไม่ใช่แค่ transcript

ยิงเสียง 20 ไฟล์เดิมผ่าน production config เต็มรูปแบบ (`SYSTEM_INSTRUCTION` + `SEARCH_FUNCTION` tool +
`run_retrieval` จริงจาก DB — เหมือน `routers/voice.py`) วัดว่า **คำตอบที่พูดออกมา** ถูกไหม
(สคริปต์: `backend/app/scripts/test_full_pipeline_answers.py`)

**ผล: ตอบถูก 14/20 = 70% | เรียก tool ถูก 20/20 = 100%**

แยกตามคำ: CAMT 4/4 ✓, **DITC 4/4 ✓** (แม้ raw transcript จะฟังผิดเป็น Disney/DC ก็ตาม — โมเดลเรียก
tool ด้วย query "DITC คืออะไร ทำอะไรบ้าง" ถูกทุกครั้ง เพราะเข้าใจเจตนาจาก context ทั้งประโยค ไม่ได้
พึ่ง transcript ดิบ), DII 4/4 ✓, SE 1/4 ✗, MMIT 1/4 ✗

**6 ข้อที่ตอบผิด ไม่มีข้อไหนเกี่ยวกับเสียง/STT เลย:**
- **SE (3/4 พัง):** ระบบตอบตรง ๆ ว่า "ไม่มีข้อมูลค่าเทอมวิศวกรรมซอฟต์แวร์ในฐานข้อมูล" — เป็น**ช่องโหว่
  ฐานความรู้จริง** (ข้อมูลค่าเทอม SE ไม่มีอยู่ใน `documents`) ต้องแก้ที่ scraper/เนื้อหา ไม่เกี่ยวกับเสียง
- **MMIT (3/4 พัง):** คำตอบพูดคุณสมบัติ (จบ ม.6, เกณฑ์ ทปอ.) ถูกต้องตามเนื้อหา แต่ไม่พูดคำว่า "MMIT"
  ซ้ำในประโยคคำตอบ — **น่าจะเป็นข้อจำกัดของวิธีวัดผลเอง** (เช็คแค่คำ "MMIT" โผล่ในคำตอบไหม) ไม่ใช่
  คำตอบผิดจริง ควรอ่านคำตอบเต็มด้วยตาอีกทีก่อนสรุปกับอาจารย์ (ดูไฟล์ `real_voice_pipeline_result.txt`)

**สรุปเชิงตัดสินใจ: ไม่มีปัญหาเสียง/STT ที่ต้องแก้เพิ่ม** DITC ที่ดูน่ากลัวตอนวัด raw transcript
(0/4) กลายเป็น 4/4 ถูกต้องสมบูรณ์เมื่อวัดที่คำตอบจริง — ตรงตามสมมติฐานเดิมที่ตั้งไว้ก่อนทดสอบว่า
transcript ผิดไม่จำเป็นต้องแปลว่าคำตอบผิดตาม (เห็นสัญญาณนี้มาก่อนแล้วจาก log การทดสอบด้วยเสียงจริง
ของ `voice_pipeline_dev.py` ที่ transcript ขึ้น "Dead Sea คืออะไร" แต่ tool call ยิง query "DITC
คืออะไร" ถูกต้อง) **ไม่เพิ่ม alias "Disney"→"DITC" เด็ดขาด** เพราะอันตราย — ถ้ามีคนถามเรื่อง Disney
จริง (เช่นถามถึง Disney+ หรือโครงการความร่วมมือ) จะถูกแปลงเป็นคำถามเรื่อง DITC ผิด ๆ ทันที และจากผล
การทดสอบนี้ก็ไม่มีความจำเป็นต้องเสี่ยงแบบนั้นเลยตั้งแต่แรก

## หมายเหตุ: [TIMEOUT] ในไฟล์ผลลัพธ์คืออะไร

สคริปต์ทดสอบตั้ง watchdog 30 วิ (STT-only) / 45 วิ (full pipeline) รอสัญญาณ `turn_complete` จาก
Gemini ถ้าเกินเวลาจะตัดแล้วต่อท้าย transcript ด้วย `[TIMEOUT]` — **ตรวจสอบแล้วว่าไม่กระทบความถูกต้อง
ของ transcript**: ไฟล์ที่ติด `[TIMEOUT]` มี transcript ที่สมบูรณ์ตรงกับประโยคต้นฉบับทุกคำ (เช่น
`'อยากทราบว่าคณะแคมป์มหาวิทยาลัยเชียงใหม่คืออะไร [TIMEOUT]'` ตรงกับต้นฉบับเป๊ะ) เพราะการถอดเสียง
คำพูดของผู้ใช้ (`input_transcription`) เสร็จเร็วกว่าที่โมเดลจะพูดตอบเสร็จมาก — `[TIMEOUT]` ที่แปะมา
คือรอ**เสียงตอบของโมเดลเอง**เกิน 30 วิ ไม่ใช่ตัดกลางคำพูดของผู้ใช้ ตัวเลขในรายงานนี้เชื่อถือได้
