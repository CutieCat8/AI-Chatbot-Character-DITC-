# ADR: ใช้หน้า HTML report preview สำหรับรายงาน PDF

- **สถานะ:** ตัดสินใจแล้ว (2026-09-27)
- **บริบท:** รายงาน PDF รุ่นแรกสร้าง HTML ในหน้าต่างใหม่ ส่วนรุ่นถัดมา reuse component ของ dashboard
  แล้วเปิด print dialog ทันที แม้กราฟตรงกับหน้าเว็บ แต่ผู้ใช้ไม่เห็นตัวอย่างเอกสารก่อนพิมพ์ รายการหัวข้อ
  บางส่วนตกขอบ และ layout แบบ dashboard ไม่เหมาะกับเอกสารที่ต้องอ่านย้อนหลัง

## ตัวเลือกที่พิจารณา

1. เปิด print dialog จากหน้า dashboard ทันที
2. reuse component dashboard ใน print layer ที่ซ่อนไว้
3. สร้าง route รายงาน HTML แยก พร้อมกระดาษ A4, preview toolbar และ print stylesheet

## การตัดสินใจ

เลือกข้อ 3 ตามรูปแบบ report viewer ของโปรเจกต์ TaxBuddy เพราะผู้ใช้สามารถตรวจข้อมูลก่อนพิมพ์ได้ และ
สามารถจัดลำดับข้อมูลสำหรับเอกสารโดยไม่ถูกจำกัดด้วย layout ของ dashboard ข้อความและ SVG ยังคงคมชัด
เมื่อบันทึกเป็น PDF โดยไม่ต้องจับภาพทั้งหน้า

รายงานแบ่งเป็น 2 หน้า A4 portrait หน้าแรกแสดง KPI, กราฟแนวโน้มพร้อมจำนวนบนทุกแท่ง และสถานะการตอบ
หน้าที่สองแสดงตารางหัวข้อทั้งหมดโดยไม่ใช้การ์ดโดนัทขนาดใหญ่ มี toolbar สำหรับกลับ พิมพ์ และบันทึก PDF

## ผลกระทบ

- URL รายงานมี `start`/`end` จึงเปิดซ้ำหรือ refresh ได้ และโหลดข้อมูลใหม่จาก API
- ไม่เปิด pop-up และไม่ติด pop-up blocker
- ปุ่มพิมพ์และบันทึก PDF ใช้ print dialog ของ browser โดยปุ่มหลังตั้งชื่อเอกสารตามช่วงวันที่
