# ADR: เลือก embedding model สำหรับ RAG — multilingual-e5-large

- **สถานะ:** ตัดสินใจแล้ว (2026-09-02)
- **บริบท:** ต้องเลือก embedding provider ก่อนเริ่ม index ข้อมูลจริงครั้งแรก (`EMBEDDING_PROVIDER` เป็น
  `fake` มาตลอด ยังไม่เคย index จริงเลยสักแถว) — เป็นจังหวะเดียวที่เปลี่ยนได้ฟรี เพราะถ้ารอจน index
  ข้อมูลจริงไปแล้วค่อยเปลี่ยน ต้องรื้อ schema `pgvector` (มิติเวกเตอร์) ใหม่ทั้งหมด

## ตัวเลือกที่พิจารณา

| ตัวเลือก | ค่าใช้จ่าย | ข้อมูลออกนอกเครื่อง (PDPA) |
|---|---|---|
| `text-embedding-3-small` (OpenAI) | เสียเงินต่อ token | ส่งออก — ไม่ทดสอบตอนนี้ (ยังไม่มี key และตกลงกันว่ายังไม่ขอ) |
| `BAAI/bge-m3` | ฟรี รันเอง | ไม่ออกนอกเครื่อง |
| `intfloat/multilingual-e5-large` | ฟรี รันเอง | ไม่ออกนอกเครื่อง |

เทียบเฉพาะ 2 ตัวหลัง (รันเองได้ฟรี ไม่ต้องมี API key เหมาะกับ PDPA มากกว่าด้วย) — ยังไม่ทดสอบ
`text-embedding-3-small` เพราะยังไม่มี `OPENAI_API_KEY` และตกลงกันว่ายังไม่ขอตอนนี้

## วิธีวัด

รวบรวมคำถาม 20 ข้อที่คาดว่าคนจะถามหน้าตู้จริง — **จงใจเขียนแบบคนพูดปกติ ไม่ลอกคำจากเอกสาร**
(เช่น "อยากเป็นโปรแกรมเมอร์ ควรเรียนอะไรดี" ไม่ใช่ "หลักสูตรวิศวกรรมซอฟต์แวร์มีอะไรบ้าง") เพราะจุดประสงค์
คือวัดว่า embedding จับ "ความหมาย" ได้ไหมตอนคำไม่ตรงกับเอกสาร ไม่ใช่วัดว่า keyword ตรงกันไหม
(ถ้าคำตรงกัน keyword search ธรรมดาก็ชนะได้อยู่แล้ว ไม่ต้องพึ่ง embedding)

แต่ละคำถามระบุ "เอกสารที่ควรตอบ" ไว้ล่วงหน้า (ตรวจจาก title จริงใน DB) แล้ววัด **recall@3**
(เอกสารที่ถูกต้องติดอยู่ใน top-3 ผลลัพธ์ไหม) — สคริปต์: `backend/app/scripts/benchmark_embeddings.py`

## ผลการทดสอบ

| โมเดล | recall@3 | latency เฉลี่ยต่อคำถาม (embed query) |
|---|---|---|
| BAAI/bge-m3 | 14/20 = **70%** | 220ms |
| **intfloat/multilingual-e5-large** | **17/20 = 85%** | **213ms** |

BGE-M3 มีอาการ **"เอกสารเดียวครอบจักรวาล"** ชัดเจน — chunk ของเอกสาร DTM ติด top-3 เกือบทุกคำถาม
แม้ไม่เกี่ยวข้องเลย (เช่นคำถามเรื่องวาดการ์ตูน/ทำเกม/ค่าเทอม) ทำให้พลาดคำตอบที่ถูกจริงบ่อย
ส่วน multilingual-e5-large ไม่มีปัญหานี้ในระดับเดียวกัน

คำถามที่ทั้งสองโมเดลพลาด (#16, #20) เป็นคำถามกว้างมากที่ไม่มีเอกสารเฉพาะเจาะจงตอบตรง ๆ อยู่แล้ว
ไม่ใช่ข้อจำกัดของ embedding model

## การตัดสินใจ: ใช้ **multilingual-e5-large**

เหตุผลไม่ได้อยู่ที่ตัวเลข 85% vs 70% เพียงอย่างเดียว (ต่างกัน 3 ข้อจาก 20 ข้อ ยังไม่ถือว่าชี้ขาดทาง
สถิติด้วยชุดทดสอบขนาดนี้) แต่เป็นเพราะ **อาการ "ตอบผิดซ้ำ ๆ แบบเดาไม่ได้" ของ BGE-M3 สร้างความเสียหาย
กว่าการตอบว่าไม่รู้** — ผู้ใช้ที่ถามเรื่องทำเกม/วาดการ์ตูน แล้วได้คำแนะนำเป็นสาขาบริหารเทคโนโลยีดิจิทัล
ที่ไม่เกี่ยวเลย จะเสียความน่าเชื่อถือของระบบมากกว่าการที่ระบบตอบตรง ๆ ว่าไม่มีข้อมูล

## ผลกระทบต่อระบบ

- `EMBEDDING_DIM` เปลี่ยนจาก 1536 → **1024** — ต้องมี Alembic migration ปรับมิติคอลัมน์
  `document_chunks.embedding` (`8d76d39db984_embedding_dim_1536_to_1024_for_e5_large.py`)
- `embedder.dim` อ่านจากโมเดลที่โหลดจริงเสมอ (ไม่ hardcode ใน `.env`) — `main.py` เช็คตอน startup
  ว่ามิติของ embedder ตรงกับคอลัมน์ใน DB จริงไหม ไม่ตรง = fail ทันทีพร้อม error ชัดเจนว่าต้องแก้อะไร
  (กันปัญหาเดิมไม่ให้เกิดซ้ำเวลาเปลี่ยนโมเดลอีกในอนาคต)
- รันเองบนเครื่อง ไม่ต้องมี API key — สอดคล้องกับ PDPA (ข้อมูลคำถามผู้ใช้ไม่ต้องส่งออกไป third-party
  เพื่อ embed) และไม่มีค่าใช้จ่ายต่อการใช้งาน
